- **No Liquid inside `{% stylesheet %}` / `{% javascript %}`.** Per-instance values go through inline `style="--x:…"`
  or through an inline `<style>` you print from Liquid.

- **core REPORT §9.1, check it in your render:** `.env2-section a{color:inherit}` (0,1,1) outranks

  `elmsnest-v2-buy` and `elmsnest-v2-pdp-card` already comply; `_verify.js` measures it and currently reports zero
  failures.
- **core REPORT §9.2:** never use `--en-warning-text` / `-success-` / `-error-` / `-info-`. They are cream-era.
- Section root, per the shared CONTRACT:
  `<section id="env2-coll-<name>" data-env2-coll-<name> class="env2-section" dir="rtl" style="scroll-margin-top:90px;--env2-stars:.34">`,

## 1. `elmsnest-v2-ground-collection` — the night measured in px (§3.1)

```liquid
{% render 'elmsnest-v2-ground-collection' %}
```
**Inputs:** none. **Prints:** one `<style id="env2-ground-collection">`. **Called by:** `elmsnest-v2-coll-scene`,
once, at the top of its markup. **Nowhere else.**

Everything it writes is scoped `html body.hdt-page-type-collection …` — (0,2,2), deliberately, because the core's
generic side-page ground is `body[class*="hdt-page-type-"]:not(.hdt-page-type-index)` at (0,2,1) and a plain
`body.hdt-page-type-collection` (0,1,1) would lose to it. No other template can be touched.

What it does:

1. The §3.1 sky, **in pixels, not percentages** — `#0b1526 0px → #0a1120 620 → #080e1c 1500 → #060a14 2600 →
   #04070e 3800 → #020306 5000` — painted on a fixed `background-size:100% 5000px` box anchored at the top, with
   `#020306` filling everything below it. A 6-product page and a 27-product page therefore reach the same darkness
   at the same distance from the top, which is the whole point of §3.1.
2. Kalles' wrappers (`#wrapper .main-content main #MainContent .hdt-main-content .hdt-page-content
   .shopify-section`) → `background:transparent`.
3. Zeroes the top gap on the first section, so the scene runs full-bleed under the transparent 70 px header.
4. `overflow-x:hidden` on the collection body.
5. **The §3.2 tap-target floor, on this template only:** `.env2-btn--sm` is 36 px tall on desktop in the core
   (it was sized for the PDP related row) and only reaches 44 px under 900 px. Here it is floored at 44 px on both
   viewports for `.env2-btn--sm` and for `.env2-pdp-card__action .env2-btn`. Measured in `_plumbing.html`: 36 → 44.
6. Two belts that keep a left-over Kalles toolbar or banner from painting cream if one survives in the template.

**Consequences for you:** no section paints a background. The only card surface anywhere on this page is the scrim
`var(--env2-scrim)` + your own `backdrop-filter:blur(10px)`, used exactly twice (§3.1) — and
`elmsnest-v2-pdp-card` with `variant:'scene'` is that surface, so you never hand-roll it.

## 2. `elmsnest-v2-coll-axis` — the parser, and the single source of every number (§3.4, §6.19)

This is the file the page stands on. **No length, quantity, watt, price or per-unit figure may be typed into a
section.** They all come from here, and here they all come from `product.options_with_values[0]` and
`variant.price`.

### 2.1 Call signatures

```liquid
{%- capture env2_axis -%}
  {%- render 'elmsnest-v2-coll-axis', product: product -%}
{%- endcapture -%}
{%- assign env2_recs = env2_axis | split: '~~R~~' -%}
{%- assign env2_meta = env2_recs[0] | split: '~~F~~' -%}
{%- for env2_rec in env2_recs offset: 1 -%}
  {%- assign s = env2_rec | split: '~~F~~' -%}
  …{{ s[3] }} {{ s[5] }} — <bdi>{{ s[10] }}</bdi> ₪…
{%- endfor -%}
```
```liquid
{%- render 'elmsnest-v2-coll-axis', product: product, emit: 'json' -%}
```

A snippet's own `{% assign %}` does **not** leak to its caller — `{% render %}` is an isolated scope — so the model
is **printed** and you split it back into Liquid variables. This is the convention
`snippets/elmsnest-v2-pdp-variants.liquid` already ships on the PDP. Keep it.

| input | meaning |
|---|---|
| `product` | required. Blank, or no options / no variants → **prints nothing at all**, so `env2_recs.size > 1` is your guard. |
| `emit` | `'rows'` (default) or `'json'`. |
| `json_id` | id of the `<script>` in json mode. Default `env2-coll-axis-<handle>`. |
| `per_unit_word` | override for the per-unit noun. Blank → `₪ למטר` for a length axis, `₪ ליחידה` for a quantity axis. The path collection prints `₪ לנקודת אור` (graft C2) — that is a **section** word choice, so the section passes it and the snippet never guesses it. |

### 2.4 The parse, against every real value in `data.json`

```
"5 מ׳ / 20 נורות"        → 5    m     מ׳     · number2 20  unit2 led (נורות)
"12×2 מ׳ / 780 LED"      → 12   area  מ׳     · area_h 2  · number2 780 unit2 led
"1.5×1.5 מ׳ / 96 LED"    → 1.5  area  מ׳     · area_h 1.5 · number2 96
"2 יחידות" / "1 יחידה"    → 2/1  qty   יח׳
"4 יח׳"  and  "4 'יח"     → 4    qty   יח׳    ← the live data carries the ASCII-apostrophe form on
                                                waterproof-solar-deck-step-lights; BOTH parse
"10 נורות"               → 10   led   נורות  ← a bulb count, NOT a length
"6W" / "10W"             → 6/10 w     W
"3000K" / "אור חם 3000K"  → 3000 k     K      ← the number need not lead
"72 LED / 100W"          → 72   led   LED    · number2 100 unit2 w
"יחידה אחת"              → ''   ''           ← a word is not a number
"לבן" "שחור" "דגם A" "Default Title" "כחול" "RGB צבעוני" "USB" "זוג"   → ''  ''
```

**`area` is not a length.** `decorative-led-net-lights` is sold by area and §4.5 non-negotiable 3 says it never
appears as a length. `measured` is `0` and `is_area` is `1` for it. `min_number`/`max_number` still carry the first
dimension so the off-scale band can print the span honestly; a section that puts an `is_area` product on a metre
rail has broken the spec.

### 2.6 Building the rail's stop set — the exact Liquid the ruler must use (§3.4)

The snippet is product-scoped by design (a Shopify `{% render %}` may not recurse). The union is eight lines, and
this is the only place they should ever be written:

```liquid
{%- assign env2_nums = '' -%}{%- assign env2_off = 0 -%}
{%- for p in collection.products -%}
  {%- capture env2_a -%}{%- render 'elmsnest-v2-coll-axis', product: p -%}{%- endcapture -%}
  {%- assign env2_r = env2_a | split: '~~R~~' -%}
  {%- assign env2_m = env2_r[0] | split: '~~F~~' -%}
  {%- if env2_m[9] == '1' and env2_m[3] == env2_unit -%}
    {%- for env2_rec in env2_r offset: 1 -%}
      {%- assign s = env2_rec | split: '~~F~~' -%}
      {%- assign env2_k = '|' | append: s[3] | append: '|' -%}
      {%- if s[3] != '' and s[4] == env2_unit and env2_nums contains env2_k == false -%}…{%- endif -%}
```

(`contains … == false` is not valid Liquid — use `{%- unless env2_nums contains env2_k -%}`. That is the one

## 3. `elmsnest-v2-coll-rail` — one product's dot rail and its stop states (§4.2, graft C1)

**There is no JavaScript in this mechanism.** Every stop's answer is printed into the DOM and CSS chooses between
them, so the page narrows with scripting disabled. `_verify.js` proves it in a `javaScriptEnabled:false` context.

### 3.1 The states

| state | when | what the row does |
|---|---|---|
| `span` | the `הכול` stop | prints the whole range — `5–22 מ׳` — with the house price rule (`elmsnest-v2-price`) |
| **`below`** | the stop is under the product's smallest value | answers with its smallest offering, which **overshoots** the stop. Full price, full per-unit line. *(decor at `3 מ׳`: Edison answers `5 מ׳ — 139.90 ₪`)* |
| **`at`** | the stop is inside `min…max` | the value **at or immediately above** the stop, and its exact price. *(decor at `10 מ׳`: rope `12 מ׳ — 99.90 ₪`, crystal `11 מ׳ — 109.90 ₪`, globe `10 מ׳ — 169.90 ₪`)* |
| **`beyond`** | the stop is past `max` | the row **dims to .4** and prints `האורך המרבי: 8 מ׳` plus that variant's price. **Never `display:none` — §4.2 n-n 2, §6.6.** |
| `off` | the product's axis is not in this unit (colour / model / no number / **area**) | `.env2-coll-rail--off`, no dots, no span, only your `off_note`. The product belongs in a band (§4.3), not on the rail. |

### 3.2 Call signatures

```liquid
{# once per page, before any rail #}
{% render 'elmsnest-v2-coll-rail', css: true %}
{% render 'elmsnest-v2-coll-rail', emit: 'css', stops: env2_stops, rail_max: env2_rail_max,
          scope: '.env2-coll-ruler__body' %}

{# once per product row #}
{%- capture env2_short -%}
  {%- render 'elmsnest-v2-coll-rail', product: p, stops: env2_stops, unit: 'm', emit: 'short' -%}
{%- endcapture -%}
<div class="env2-coll-ruler__row" data-short="{{ env2_short | strip }}">
  …title, axis caption…
  {% render 'elmsnest-v2-coll-rail', product: p, stops: env2_stops, unit: 'm',
            rail_max: env2_rail_max, miss_label: 'האורך המרבי', off_note: env2_note %}
  …price column, action…
</div>
```

| input | meaning |
|---|---|
| `product` | required for `rail` / `short`. Blank → nothing. |
| `stops` | the page's stop set, an **ascending comma list**: `'3,6,10,15,22,30'`. Built by §2.6, never typed. `הכול` is implicit and always rendered — do **not** put it in the list. |
| `unit` | the rail's unit key (`m` `qty` `led` `w` `k`). A product whose axis unit differs, or is `area`, or has no number, renders `off`. |
| `rail_min` / `rail_max` | the rail's end numbers. Defaults 0 and the largest stop. |
| `miss_label` | the `beyond` label. Defaults `האורך המרבי` (m), `הכמות המרבית` (qty), `המידה המרבית` (other). §4.2 fixes only the metre wording; the section owns the rest. |
| `off_note` | one line inside an `off` rail — the net gets `נמדדת לפי שטח, לא לפי אורך` (§3.4). Blank → nothing printed. |
| `per_unit_word` | path prints `₪ לנקודת אור` (C2). |
| `show_per` | `false` to suppress the derived per-unit line (the ruler's `show_unit_price` setting). |
| `scope` | (`css` emit) the selector the generated rules hang under. Default `.env2-coll-ruler__body`. **It must be a SIBLING of the radios and come after them in the DOM.** |
| `emit` | `'rail'` (default) · `'short'` · `'css'`. |
| `css` | `true` → the static stylesheet only. |

### 3.3 What it prints, and the class names

```html
<div class="env2-coll-rail" data-unit="m" data-state="on" data-short="10 15 22 30"
     style="--env2-rail-max:32">
  <span class="env2-coll-rail__line"></span>
  <span class="env2-coll-rail__dot" data-n="5" data-pick="all 3" style="--env2-rail-p:15.63%"
        title="5 מ׳ / 20 נורות"></span>
  <span class="env2-coll-rail__v env2-coll-rail__v--all" data-stop="all" data-state="span">
    <b class="env2-coll-rail__val"><bdi>5–22</bdi> מ׳</b>
    <span class="env2-coll-rail__price">…elmsnest-v2-price…</span>
  </span>
  <span class="env2-coll-rail__v" data-stop="10" data-state="at" data-n="11" data-variant-id="41…">
    <b class="env2-coll-rail__val"><bdi>11</bdi> מ׳</b>
    <span class="env2-coll-rail__price"><bdi>109.90</bdi> ₪</span>
    <span class="env2-coll-rail__per"><bdi>≈9.99</bdi> ₪ למטר</span>
  </span>
  <span class="env2-coll-rail__v" data-stop="30" data-state="beyond">
    <span class="env2-coll-rail__miss">האורך המרבי: <bdi>22</bdi> מ׳</span>
    <span class="env2-coll-rail__price env2-coll-rail__price--miss"><bdi>179.90</bdi> ₪</span>
  </span>
</div>
```

`emit:'short'` prints **only** `10 15 22 30` — no markup — so you can put it on the ROW and dim the whole row.
A product with no short stop prints an empty string. The rail root carries the same `data-short`, and the generated
ruleset resets a nested duplicate to `opacity:1`, so the two can never compound to `.16`.

The one class you must supply yourself: **put `.env2-coll-rail__cursor` on the ruler's cursor knob**, inside the
scope element. The generated CSS moves it. It is the second and last round thing on this page (§3.1).

### 3.4 What `emit:'css'` generates — this is the whole narrowing mechanism

Per stop `N` of `stops`, plus `all`:

```css
#env2-stop-N:checked ~ SCOPE .env2-coll-rail__v{display:none}
#env2-stop-N:checked ~ SCOPE .env2-coll-rail__v[data-stop="N"]{display:flex}
#env2-stop-N:checked ~ SCOPE .env2-coll-rail__dot[data-pick~="N"]{transform:scale(1.5);background:var(--env2-glow);box-shadow:…}
#env2-stop-N:checked ~ SCOPE [data-short~="N"]{opacity:.4}
#env2-stop-N:checked ~ SCOPE [data-short~="N"] [data-short~="N"]{opacity:1}
#env2-stop-N:checked ~ SCOPE .env2-coll-rail__cursor{inset-inline-start:P%}
```

**Your side of the contract** (this is `howmuch/index.html:229–262`, and it is what the ruling exists for):

```html
<input type="radio" name="env2-stop" id="env2-stop-all" class="env2-sr" checked>
<input type="radio" name="env2-stop" id="env2-stop-3"  class="env2-sr">
… one per stop …
<div class="env2-coll-ruler__body">                    ← the scope, a SIBLING, after the radios
  <label class="env2-pill" for="env2-stop-all">הכול</label>
  <label class="env2-pill" for="env2-stop-3"><bdi>3</bdi> מ׳</label>
  <div class="env2-coll-ruler__master">
    <span class="env2-coll-rail__line"></span><span class="env2-coll-rail__cursor"></span>
  </div>
  …the rows…
</div>
```
The ids are `env2-stop-<key>` where `<key>` is the stop number **with `.` replaced by `_`** (`6.5` → `6_5`;
see risk 12) or `all`.
`3.4`'s eleven-line JS enhancement only writes `#len-10` into the URL; **it never narrows anything.**

Proof: `_ruler-at-10.png` — the cursor at the `10 מ׳` position, three lit dots, three real prices with their
per-unit lines, and the Edison row dimmed printing `האורך המרבי: 8 מ׳ · 179.90 ₪`.

### 3.5 Two bidi rules you cannot skip

1. **The `≈` goes INSIDE the `<bdi>`** — `<bdi>≈9.99</bdi> ₪ למטר`. Left outside, the RTL algorithm moves it to
   the far edge and the page prints `9.99 ₪ למטר≈`. This was measured, not guessed; the first render of
   `_plumbing.html` had it wrong.
2. **A slash- or dash-joined pair goes inside ONE `<bdi>`** — `<bdi>5–22</bdi> מ׳`, `<bdi>6W/12W</bdi>`,
   `<bdi>1/4/8/12</bdi>` (§3.2, §6.12). `brief/lint.py` fails a build that splits one.

## 5. `elmsnest-v2-coll-paginate` — §3.7

```liquid
{# inside the Liquid paginate block over collection.products, by 50 #}
{% render 'elmsnest-v2-coll-paginate', paginate: paginate, collection: collection %}
{% render 'elmsnest-v2-coll-paginate', collection: collection, emit: 'note' %}
{% render 'elmsnest-v2-coll-paginate', css: true %}
```

`paginate` is only in scope inside that block and `{% render %}` does not inherit the caller's scope, **so you must
pass it explicitly**. That is the one mistake to avoid.

- `paginate.pages <= 1` → the snippet prints **absolutely nothing**. At 27 products with `by 50` that is always the
  case, which is the §3.7 decision, printed once by `emit:'note'`:
  `27 מנורות בעמוד אחד. אין עמוד 2.` — that line belongs in **§4.5's foot**.
- The control carries `?sort_by=` onto every page link: from `sort_by:` if you pass it, else `collection.sort_by`,
  appended only when Shopify's own URL does not already hold one. **`best-selling` and `popularity` are dropped on
  the floor** (§6.5 — one test order exists in the store's history).
- Classes: `.env2-coll-paginate` · `__step` (`rel="prev"` / `rel="next"`) · `__count` · `__list` · `__n`
  (`.is-current`, `aria-current="page"`) · `__note`. Plain anchors on one hairline, radius 0, 48 px tap targets
  (44 under 900 px). Never a `<select>`, never "load more", never infinite scroll (§6.1).

## 9. Risks a section engineer must know

1. **`{% render %}` is an isolated scope, and `paginate` lives only inside its own block.** Pass `paginate:`,
   `collection:`, `product:` explicitly. A snippet's `{% assign %}` never reaches you — that is why every model here
   is *printed* and split.
2. **`x contains 'y' == false` is not valid Liquid.** Use `{%- unless x contains 'y' -%}`. It parses without
   erroring and then behaves unpredictably; it is the single most likely silent bug in this build.
3. **Do not start a `comment` line inside a `{% liquid %}` tag with `§` or `(`.** Shopify accepts it; the
   python-liquid harness that renders the offline proofs does not, and you will not be able to prove your section.
   Start those lines with a word.
4. **`area` is not a length.** `decorative-led-net-lights` has `unit: 'area'`, `measured: '0'`, and a `min`/`max`
   that are the *first dimension only*. Branch on `meta[9]` (measured), never on `min`/`max` being non-empty.
   §4.5 non-negotiable 3: it never gets a ledger row.
5. **`solar-floodlight-ip67-remote-timer` parses as `led`, not `w`.** `72 LED / 100W` puts 72 first, so
   `unit = led`, `number2 = 100`, `unit2 = w`. §3.4 calls that axis "watts"; if a section wants the wattage it must
   read `number2`. Spot ships in `price` mode anyway, so nothing depends on it today.
6. **`יחידה אחת` yields no number** (`powerful-solar-garden-light`, `solar-garden-spotlight-52-led`). That is
   deliberate and it is what makes §3.4's path union come out as `1 2 4 6 8 12` and puts `powerful-solar-garden-light`
   in the off-scale band. Do not "helpfully" map the word to 1.
7. **The dot rail must not clip at the inline edge** (`index`'s live defect). Give the row
   `overflow-x:auto; overscroll-behavior-inline:contain` and a fading mask — and never let the *document* scroll
   horizontally at 360 px. `shot.js` prints `horizontal-overflow`; it is `false` on both viewports today.
8. **The `.env2-btn--sm` tap target was 36 px on desktop.** The ground snippet floors it at 44 px for this template
   only. If you build a control that is not an `.env2-btn`, floor it yourself.
9. **`<a class="env2-btn">` is still ink-on-glow at 1.21:1** (core REPORT §9.1, unfixed by design this round).
   Every primary CTA is a `<button>` in a form, or sets `color:var(--env2-btn-ink)` from its own selector.
10. **The scrim card is `variant:'scene'` on `elmsnest-v2-pdp-card`, and it is used exactly twice** (§3.1). A third
    scrim surface anywhere on the page is a breach.
11. **Render the glyph sprite once, before any plate**, or every plate on the page is an empty box. The card with
    `glyph:'auto'` does not render it for you.
12. **A stop key is the number with `.` replaced by `_`.** `#env2-stop-6.5` reads to a CSS parser as id
    `env2-stop-6` plus class `5`, and narrowing silently stops working — so the rail keys the stop `6.5` as `6_5`
    in `data-stop`, `data-pick`, `data-short` and every generated selector. **Your radio ids, your labels' `for`,
    and the `#len-` hash must use the same transform:** `{%- assign k = stop | replace: '.', '_' -%}`. The six
    stops §3.4 ships for decor and path are integers, so it does not bite today — but `stops_max` is a schema
    setting and `6.5`, `9.5` and `1.5` are all real values on the decor axis.
13. **`kicker` repeats.** `elmsnest-v2-pdp-card` derives the place kicker from `product.type`, which is identical
    for every product in a collection. Pass `kicker: 'none'` on all but the first card of any column, or the page
    prints the same gold line seven times (§3.5, and it is what sank `places`).
14. **Prices are strings everywhere in this plumbing**, already rounded to the agora. Never `| plus: 0` one and
    re-format it; use `price_cents` if you need arithmetic.
