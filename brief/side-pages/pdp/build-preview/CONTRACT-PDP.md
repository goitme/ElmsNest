## 0. What is already there, and what you must not do

`snippets/elmsnest-v2-core.liquid` is rendered from `layout/theme.liquid` on **every** template. It already provides the
tokens, Frank Ruhl Libre + Heebo, `.env2-section` / `.env2-wrap` / `.env2-h` / `.env2-lead` / `.env2-eyebrow` /
`.env2-kicker` / `.env2-price` / `.env2-btn` / `.env2-link` / `.env2-hair` / `.env2-stars`, `[data-lamp]`, the keyframes,
the reduced-motion block, `window.env2` and the `form[data-env2-buy]` → `/cart/add.js` → cart-drawer handler.

- **Do not render `elmsnest-v2-fonts` or `elmsnest-v2-base`** from any PDP section (§8.2). They are a no-op or a stub.
- **Do not redefine a core token or restyle a core class.** Size a shared class from your own selector
  (`.env2-pdp-facts__price .env2-price{--env2-price-size:30px}`).
- **`elmsnest-v2-ground-product` is rendered by `elmsnest-v2-pdp-stage` only**, once, exactly as the homepage hero
  renders `elmsnest-v2-ground-index`.
- **No Liquid inside `{% stylesheet %}` / `{% javascript %}`.** Per-instance values go through inline `style="--x:…"`.
- **No file may contain three double quotes in a row** — it breaks the GraphQL upload.
- **§8.3, check this in your render:** `.env2-section a{color:inherit}` (0,1,1) outranks `.env2-btn{color:…}` (0,1,0),
  so an **anchor** styled as the filled pill is ink-on-glow at 1.21:1. Every primary CTA is a `<button>` in a form, or
  sets `color:var(--env2-btn-ink)` from its own selector. `elmsnest-v2-buy` and `elmsnest-v2-pdp-card` already comply.
- **§8.4:** never use `--en-warning-text` / `-success-` / `-error-` / `-info-`. Write your own state colour from the palette.
- Section root, per the shared CONTRACT: `<section id="env2-pdp-<name>" data-env2-pdp-<name> class="env2-section" dir="rtl"
  style="scroll-margin-top:90px;--env2-stars:.34">`, and your JS ends with the `env2.observe(el)` / fallback line.

## 1. `elmsnest-v2-ground-product` — the PDP ground (§3.1)

```liquid
{% render 'elmsnest-v2-ground-product' %}
```
**Inputs:** none. **Prints:** one `<style id="env2-ground-product">`. **Called by:** `elmsnest-v2-pdp-stage`, once, at the
top of its markup. Nowhere else.

Everything it writes is scoped `html body.hdt-page-type-product …` — (0,2,2), deliberately, because the core's generic
side-page ground is `body[class*="hdt-page-type-"]:not(.hdt-page-type-index)` at (0,2,1) and a plain
`body.hdt-page-type-product` (0,1,1) would lose to it. No other template can be touched.

What it does: the short night sky `#0f1a2f → #0f1a2f 20% → #070b15 56% → #020306` on the body · Kalles' wrappers
(`#wrapper .main-content main #MainContent .hdt-main-content .hdt-page-content .shopify-section`) → `background:transparent`
· zeroes the top gap on the first section so the stage runs under the transparent 70 px header · `overflow-x:hidden` on the
product body · and, `@media (max-width:900px)`, declares `--env2-pdp-bar-h:78px` **and** `padding-block-end` on the body so
the sticky bar can never cover the footer.

**Consequences for you:** no section paints a background (the only card surface on the page is the scrim, used twice —
the mobile bar and the C diptych caption). `--env2-pdp-bar-h` is declared here; read it, do not redeclare it.

## 2. `elmsnest-v2-pdp-image` — the image-index resolver (§3.5 + §3.6 never-use ledger)

```liquid
{%- capture env2_i -%}
  {%- render 'elmsnest-v2-pdp-image', product: product, slot: 'hero', index: section.settings.hero_image_index -%}
{%- endcapture -%}
{%- assign env2_i = env2_i | plus: 0 -%}
{%- assign hero = section.settings.hero_image | default: product.images[env2_i] | default: product.featured_image -%}
```

| input | type | meaning |
|---|---|---|
| `product` | product | required; anything else prints `0` |
| `slot` | string | `hero` · `context` · `close` · `card` · `wall-pair` · `big` · `small` · `thumb` (default `hero`) |
| `index` | integer | the section's **1-based** range setting (1 = admin position 1 = `product.images[0]`). `0`/blank → the ledger default |
| `fallback` | integer | optional **0-based** index used when the handle is not in the ledger |

**It prints exactly one integer** — the 0-based index into `product.images` — and nothing else. It cannot return an image
object (a Liquid snippet cannot), so the `| default:` chain above is the contract: **picker override → resolved index →
featured image**. An `image_picker` file is the merchant's own upload and is deliberately **not** filtered.

Guarantees: the result is always inside `0 … product.images.size-1` (`0` when there are no images), and it is **never a
banned index for that handle** — a banned request silently steps forward to the first clean index, wrapping.

Ban ledger held in the snippet (one `assign`, one place):

- index **0** banned on the 14 §3.6 handles: `retro-solar-path-lights-set` · `warm-solar-step-deck-lights` ·
  `waterproof-solar-deck-step-lights` · `solar-garden-lantern-9-led` · `solar-garden-spotlight-52-led` ·
  `solar-security-light-100-led` · `modern-solar-path-lights-set` · `solar-floodlight-ip67-remote-timer` ·
  `decorative-led-net-lights` · `led-globe-string-lights` · `modern-led-bollard-light-5w-ip65` ·
  `rechargeable-telescopic-camping-lantern` · `swaying-solar-path-lights-ip65` · `magnetic-rechargeable-touch-wall-light`
- indices **1, 2, 3** banned on `dual-head-garden-light-10w-ip65` (there it is 1–3 that carry the text, and 0 that is clean)
- the three archetypes, from BRIEF §6: `solar-crystal-ball-string-lights` **1, 3** · `stainless-steel-solar-path-light-ip65` **2** ·
  `waterproof-led-wall-light-ip65-6w-12w` **0**

Slot defaults that ship (0-based; verified in `_plumbing-desktop.png` §4):

| handle | hero | context | close | card | wall-pair | big | small | thumb |
|---|---|---|---|---|---|---|---|---|
| `solar-crystal-ball-string-lights` | 2 | 2 | 0 | 0 | 2 | 2 | 0 | 0 |
| `stainless-steel-solar-path-light-ip65` | 0 | 3 | 3 | 0 | 3 | 3 | 1 | 3 |

**Never write `product.images[0]` (or any literal index) in a section — the lint fails the file.** Every slot goes through
this snippet. Loading rules are still yours: stage hero `loading="eager" fetchpriority="high"`, `widths:'900,1400,1800,2400'`,
everything below the fold `loading="lazy"` with explicit `width`/`height`, first gallery tile eager (AUDIT §182).

## 3. `elmsnest-v2-pdp-variants` — the ledger model (§3.6 + §4.4)

Built **once** from `product.variants`, printed in two shapes from one computation.

### 3.1 Call signatures

```liquid
{%- capture env2_model -%}
  {%- render 'elmsnest-v2-pdp-variants', product: product, axis: section.settings.price_axis_option -%}
{%- endcapture -%}
{%- assign env2_recs = env2_model | split: '~~R~~' -%}
{%- assign env2_meta = env2_recs[0] | split: '~~F~~' -%}
{%- for env2_rec in env2_recs offset: 1 -%}
  {%- assign r = env2_rec | split: '~~F~~' -%}
  …  r[3] key_a · r[10] price · r[12] per_unit · r[15] variant_id · r[17] the row's quiet variants …
{%- endfor -%}

{% render 'elmsnest-v2-pdp-variants', product: product, emit: 'json' %}   {%- comment -%} the script tag {%- endcomment -%}
```

> **It prints raw text.** In the default `rows` mode you MUST wrap the call in `{% capture %}`, or `~~F~~` lands on the page.

| input | meaning |
|---|---|
| `product` | required; blank / no variants → prints **nothing at all** |
| `axis` | `option1` \| `option2` \| `option3` \| `1` \| `2` \| `3` — the section's `price_axis_option`. Blank/`0` → detected |
| `axis2` | a second price-bearing option. Blank → detected |
| `emit` | `rows` (default) \| `json` |
| `json_id` | id of the script tag in json mode (default `env2-pdp-variants`) |

### 3.2 Axis detection (what it decides, and why)

1. If one option's value fully determines the price (all variants sharing that value share a price) **and** it has more than
   one value → that is the price axis. *(A: `אורך ומספר נורות`.)*
2. Otherwise the first **pair** of options that together determine the price becomes `axis` + `axis2`.
   *(C: `עוצמה` × `גוון אור` → four rows.)*
3. Otherwise (a single price for the whole product) the option with the most values is the row axis.
4. `product.variants.size == 1` → `meta[1] = 'single'`: there is no picker at all; §4.4's ledger is a **quantity** ledger
   posting `quantity=N` against `meta[11]`. *(B.)*

Every option that is not `axis`/`axis2` is a **quiet** axis: it never changes the price. `meta[8]` is its value count —
**when it is 1 you must not render a control** (BRIEF §11 "no one-value picker"; B's `צבע אור: צהוב חם` is printed as a fact).

### 3.6 The no-JS / JS split you are building against (§4.4)

- **No JS:** every row visible with its price, and every row buyable — one `<form method="post" action="{{ routes.cart_add_url }}">`

- **With JS:** `html.env2-js` hides `.env2-pdp-ledger__form`, the row button becomes the selector, the stage price / mirror /
  string update, `?variant=` syncs with `history.replaceState`, and the single stage `הוספה לסל` posts to `/cart/add.js`.
  The enhanced state is the *reduced* state — the CONTRACT's dim/lit inversion applied to forms.

## 8. Risks a section engineer must know

1. **The variants model prints raw text.** `{% capture %}` it. `~~R~~` / `~~F~~` on the page is your missing capture.
   Render `emit: 'json'` **once per page** (the stage); a second tag with the same id breaks `getElementById`.
2. **Every `custom.*` metafield is EMPTY at render time.** `metafields.json` is a *proposal*; nothing is written to Shopify.
   `power_source` empty → the page says **nothing** about power (C is in this state — no "חיבור לחשמל", no solar copy).
   `not_fit_for` empty → **no negative at all**; never invent one. Every section must degrade to the description bullets.
3. **`meta[8] == 1` (or `meta[18] == 1`) means do not render a picker.** B's `צבע אור: צהוב חם` is a printed fact.
4. **`money_without_currency` uses the shop's format** — four-digit totals come back with a comma (`1,359.20`). Keep them
   inside one `<bdi>` and `white-space:nowrap`.
5. **The resolver returns an index, not an image.** Keep the `| default: product.images[i] | default: product.featured_image`
   chain; dropping the last `default` renders an empty `<img>` on a product with no images.
6. **`[data-lamp]` inside a `<style>`-less section still works** — the core owns the rules. But a lamp that starts lit under
   `html.env2-js` (do-not §6.13) or one that never gets `env2.observe` will read as a bug in the capture.
7. **Anchors styled as the filled pill are 1.21:1** until the lead approves the core fix (§8.3). Use a `<button>`, or set
   the colour from your own selector, and *check the computed colour in the render*.
8. **The sticky bar reserves 78 px at the end of the document on ≤900 px** (`--env2-pdp-bar-h`, in the ground snippet). If
   your section needs a different reservation, change it in one place — do not add a second `padding-block-end`.
9. **The photo CTA is a `<a>` with no wrapper.** Give it its own grid/flex cell; do not wrap it in a `<button>`.
10. **The card emits its stylesheet only on the `css: true` call.** Forgetting it renders unstyled cards; calling it twice
    is harmless but wasteful.
11. **`elmsnest-v2-photo-url` was extended** (optional `subject`/`body`/`text`). If the integrator deploys the sections but
    not that snippet, the CTA still renders correctly — it falls back to the snippet's own default subject and body. No
    section needs a workaround.
12. **The offline harness is not Shopify.** `_build-plumbing.py` renders through python-liquid with stub `money_without_currency`
    and `image_url` filters; it proves the logic and the markup, not Shopify's exact money format or CDN URLs. The integrator
    must still grep the deployed mirror for `Liquid error` (must be 0).
